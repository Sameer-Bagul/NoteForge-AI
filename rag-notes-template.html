Foundations of RAG § 4.1
4.1.1 Motivation — Why RAG? Core Concept

LLMs have parametric knowledge baked into weights at training time. This creates three critical gaps:

  • Knowledge cutoff — the model can't answer about events after its training date
    • RAG injects live documents at inference — no retraining needed
    • Retrieval timestamp can be logged for auditability
  • Hallucination — models confabulate when uncertain
    • Grounding context forces the model to cite retrieved chunks
    • Set temperature=0 + strict system prompt for max fidelity
  • Private / proprietary data — can't fine-tune on confidential docs safely
    • RAG stays in your infra — data never leaves unless you call the LLM
"Don't fine-tune when you can retrieve. RAG gives you current, domain-specific knowledge at zero retraining cost — and you can update the knowledge base any time." — Production RAG Engineering
4.1.2 Two-Phase Architecture Architecture
📄IngestLoad docs
✂️ChunkSplit + overlap
🔢Embed→ float[]
🗄️IndexVector store
🔍RetrieveANN top-K
🧠GenerateLLM call
⬇ Offline — Indexing Phase
  1. Load raw docs (PDF, HTML, MD, DB)
  2. Split into overlapping chunks
    • 4.1 — Fixed-size / Recursive
    • 4.2 — Semantic boundary detection
  3. Embed via embedding model
  4. Upsert vectors + metadata to store
⚡ Online — Query Phase
  1. Embed incoming user query
    • 4.1 — Same model as indexing!
  2. ANN search → Top-K candidates
  3. Optional rerank + metadata filter
  4. Construct prompt → LLM → respond

4.2.2 Chunking Strategies Critical
4.2.2.a Fixed-size (Naive)

Split every N tokens regardless of content boundaries. Fast but semantically lossy.

4.2.2.a.i Parameters
512chunk_size (tokens)sweet spot for retrieval
64chunk_overlap~12.5% overlap ratio
8191model ctx limittext-embedding-3-small
4.2.2.b Recursive Character Splitter (Recommended)

Splits on a priority hierarchy of separators: "\n\n" → "\n" → " " → ""

chunking.pyPython
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=512,          # target chunk size in tokens
    chunk_overlap=64,       # sliding window overlap
    separators=["\n\n", "\n", " ", ""],
    length_function=len,
    add_start_index=True,   # store char offset in metadata
)
chunks = splitter.split_documents(docs)
4.2.2.c Advanced Strategies
  • Semantic chunking — embed each sentence, split at cosine distance drops
    • Finds natural topic boundaries automatically
    • 2–3× slower at index time; better retrieval precision
      • Use SemanticChunker from LangChain Experimental
  • Parent-document retrieval — index small child chunks, return large parent
    • Child chunk size ~128 tokens for precise matching
    • Parent chunk returned ~1024 tokens for rich context
      • Best for long-form documents like legal or medical PDFs
⚠️ Common Mistake
Don't chunk on page_content alone — always preserve source, page_num, section metadata. Without it, you can't filter by source or build citations.

Embedding Models § 4.3
4.3.1 What are Embeddings?

An embedding model maps a string → a dense float vector in high-dimensional semantic space. Semantically similar texts cluster nearby; retrieval = nearest-neighbour search.

Cosine Similarity — Retrieval Score
sim(q, d) = (q · d) / (‖q‖ × ‖d‖) ∈ [−1, 1]

4.3.3 Hybrid Search — Dense + Sparse
4.3.3.a Why hybrid?
  • Dense retrieval excels at semantic queries ("what is the policy on X")
  • Sparse / BM25 excels at keyword exact-match (product codes, names, IDs)
  • Hybrid fuses both via Reciprocal Rank Fusion (RRF) — almost always beats either alone
4.3.3.b RRF Formula
Reciprocal Rank Fusion Score
RRF(d) = Σ 1 / (k + ranki(d)) where k = 60

4.4.1 ANN Index Algorithms
4.4.1.a HNSW (Hierarchical Navigable Small World)

Default index in most vector stores. Navigates a layered proximity graph — upper layers for long hops, lower for precision.

4.4.2 Reranking Pipeline High Impact
4.4.2.a Two-stage retrieval
  1. Stage 1 — Recall: ANN retrieves Top-50 candidates cheaply (bi-encoder)
    • 5.1 — Run cosine sim in vector store (fast, approximate)
    • 5.2 — Apply metadata pre-filters (date, source, category)
  2. Stage 2 — Precision: Cross-encoder reranks Top-50 → Top-5 (expensive but accurate)
    • 5.1 — Cohere Rerank / BGE-Reranker-v2 / MS-MARCO
    • 5.2 — Cross-encoder sees (query, chunk) together — much more nuanced
reranker.pyPython
import cohere

co = cohere.Client("COHERE_API_KEY")

# Stage 1: get broad candidates from vector store
candidates = vectorstore.similarity_search(query, k=50)
docs_text = [d.page_content for d in candidates]

# Stage 2: rerank to top-5
reranked = co.rerank(
    query=query,
    documents=docs_text,
    top_n=5,
    model="rerank-multilingual-v3.0"
)
top_chunks = [candidates[r.index] for r in reranked.results]
💡 Tip — Metadata Filtering
Add filter={"source": "handbook"} to your similarity_search call to restrict retrieval to a subset of your corpus. All major stores support this.
ℹ️ When to skip reranking
If corpus <10K chunks and latency <500ms is critical, skip reranking. ANN alone is fine. Add reranker when you hit precision complaints.

4.5.2 Prompt Template Anatomy
prompt.pyPython
from langchain.prompts import ChatPromptTemplate, SystemMessagePromptTemplate

SYSTEM = """You are a precise Q&A assistant. Rules:
1. Answer ONLY from the provided context.
2. If the context doesn't contain the answer, say: "I don't know based on the provided documents."
3. Never fabricate facts. Quote relevant sentences with [Source: {source}] tags.
4. Keep answers concise — max 3 sentences unless asked to elaborate."""

HUMAN = """Context (retrieved chunks):
---
{context}
---
Question: {question}"""

prompt = ChatPromptTemplate.from_messages([
    ("system", SYSTEM),
    ("human", HUMAN),
])
4.5.2.a Key prompt engineering rules for RAG
  • Always include an explicit "if you don't know, say so" fallback — prevents hallucination
  • Delimit context with clear markers (--- or XML tags) so LLM can't confuse it with instruction
  • Include citation instructions — forces grounding + enables post-hoc verification
Evaluation & Tracing § 4.6
4.6.1 RAGAS Metrics Must Know
Faithfulness % of answer claims that are grounded in the retrieved context. Score 0–1.
Answer Relevancy cosine_sim(answer, question). Penalises verbose or off-topic replies.
Context Recall % of ground-truth sentences covered by retrieved chunks.
Context Precision % of retrieved chunks that are actually relevant. Penalises noise.
eval.pyPython
from ragas import evaluate
from ragas.metrics import (
    faithfulness,
    answer_relevancy,

)
from datasets import Dataset
